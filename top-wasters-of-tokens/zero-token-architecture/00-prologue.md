# Zero-Token Architecture

Any task that can be repeated should be paid for once. If a workflow runs the same way every time, generating code for it once and running that code forever costs zero tokens per repetition — the alternative is renting intelligence to redo settled work.

## Open questions

- How do you tell a genuinely repeatable task from one that only looks repeatable?
- What is the boundary between generated code and the agent that still has to judge?
